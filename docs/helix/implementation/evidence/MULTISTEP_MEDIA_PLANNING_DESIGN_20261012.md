# 多步骤媒体达标路径规划设计

日期：2026-10-12。状态：已废弃，仅保留历史讨论记录。用户在确认现有Coordinator逐阶段根据Gap推进的实现后，明确决定“废弃智能规划路径这条路”，取代此前暂缓决定。不再推进本稿的完整达标路径求解、统一资源点评分或相关Coordinator/Planner编排调整。继续沿用现有方式：评估当前材料Gap，内部能力无法补足时寻源，取得材料后根据实际Evidence继续内部加工与验收。下文全部为已废弃方案，不构成正式架构合同或实施计划；未修改产品代码、正式合同、生产数据或媒体。

UAT-312外部原盘接入故障仍独立开放；废弃智能规划方案不代表该故障已修复，也不自动授权生产恢复或媒体处置。

## 设计基准：达标路径与执行步骤

2026-10-12用户进一步质疑“达标路径与执行Plan分开理解”是否新增概念。检查当前实现后确认：`libra-run-coordinator.js` 在本地非stream_file分支主动签发Remux Work，并在外部Import后依据Gap选择Remux或Transcode；`external-material-work.js`预先划分search_selection、acquire_verification、import_selection。因此当前Coordinator不只是等待结果，也承载了具体媒体手段分支。仅在现有分段上增加预计完整路径评分，不能证明所比较的动作组合会由Planner实际编译并执行，可能形成一套用于评分的路线和另一套用于执行的硬编码路线。

用户随后确认核心区分：达标路径回答“用哪些手段及组合满足Acceptance”；执行步骤回答“选定手段后如何调用原子能力完成”。现有Workflow Plan主要定义第二层，而SSOT未充分独立定义第一层，导致部分路径决策降格为写死的步骤。后续文档使用“达标路径决策”和“执行Plan”，不再用无修饰的Plan同时指代两者。

撤回此前“Coordinator签发一个与Run同目标的大Work”及“选路必须塞进现有Work Planner”的建议。先明确第4节的语义合同，再决定函数与组件归属；不新增与Run同目标的包装层，不把达标路径预设为有独立生命周期的持久对象。本稿不改动SSOT或运行实现。

唯一架构依据为 [SSOT](../../TOP_DOWN_ARCHITECTURE_CONFIRMATION.md)。现场关联 [UAT-312](UAT-312_EXTERNAL_BDMV_FURIOSA_20261012.md)；不分配新的 UAT，不据此关闭既有问题。

## 1. 已确认范围与设计目标

本次仅完善 Libra 的媒体达标路径决策。对当前允许的 Acceptance 目标，组合可用生产手段，选择规划代价最低的可行路径，通过现有Work和不可变Workflow Plan落实。路径选择与执行编排不是同一个决定，但后者必须忠实落实前者。

用户已确认：

- 外部获取、Remux、转码可以组合；本地和外部取得的同类材料复用适用的加工能力，不按来源建立不同加工规则。
- 原盘不因格式被排除。应补齐原盘获取到加工的能力衔接，不能以格式黑名单绕过缺陷。此决定取代讨论早期的“外部不下载原盘”方向。
- 做种数折算入外部获取代价，不另设获取可靠性档位或做种数第二排序。
- 资源点仅为 Planner 的计算载体。选中路径的估算及依据可以随 Plan 留存用于诊断，无须对用户展示。
- 不建立点数余额、配额、消耗、结算、预留、跨 Plan 汇总或调度机制，不改变 ShelfDeck Resource Governor 等资源管理。
- 获取或中间适配环节不能替下游能力作处理资格决策。必要的正式身份、完整性、授权及产品验证仍遵循各自原子合同。

原子动作基础值沿用本次讨论：外部获取基础代价 3、Remux 1、转码 2、直接使用 0。下文做种曲线及其常量是建议值，尚不是已接受的正式版本化规则。

## 2. 一个目标、一个比较规则

Acceptance 规定目标，不按符合字段百分比计分。沿用 UAT-251/274：正常目标 S0 优先；只有满足既有转换条件才进入次级目标 S1，S1 仅有条件放宽体积和演员关系。不把 S0 与 S1 路径混在同一集合里按低价选择。

对当前目标：

1. 从当前允许使用的材料、真实 Evidence、候选声明和 Capability Catalog 生成有界候选路径。
2. 根据能力声明判断路径是否可达。缺少不可补要求、身份冲突、已知无法获取、能力不支持等，不属于可行候选。
3. 对每条可行路径计算统一规划代价，选择最小值。
4. 完全同分时按稳定路径标识决胜，仅保证确定性，不引入业务偏好。

H.264 经转码达到 HEVC 是合格候选；音轨不能通过现有能力补足则不是候选。输入差距已体现为必要动作，不再另扣“匹配度分”。超出当前 Acceptance 要求的规格也不自动加分。

做种数为 0 或 unknown 时沿用现有外部获取资格，不将公式代入视为取得下载资格；既有 Series 的仅逐集体积分配未知例外继续有效，不以本设计笼统的缺证规则覆盖它。

## 3. 简单统一的代价函数

建议：已知正整数做种数 s 的外部获取代价为：

`acquireCost(s) = 3 + 30 / (s + 5)`

3 是基础值；第二项是获取困难的附加值。做种越多，代价单调下降并接近 3。30 和 5 是明确的规划偏好常量，不代表下载耗时或成功概率。

| 做种数 | 获取代价（显示近似值） |
| --- | ---: |
| 1 | 8.00 |
| 5 | 6.00 |
| 10 | 5.00 |
| 20 | 4.20 |
| 24 | 4.03 |
| 50 | 3.55 |
| 100 | 3.29 |

`pathCost = sum(acquireCost for required acquisitions) + remuxCount + 2 * transcodeCount`

沿用各 Profile 已有获取范围与额度，不由公式授权新增 Job。当前 Movie 路径的获取次数为 0 或 1；不另改 Series 的 Scope 规则。按不同实际动作计一次，共享节点不按消费者数量重复计点。对完全同范围的候选路径比较，不拿单个 Episode 与整季比较。

转码直接生成目标容器，只计 2；若实际能力要求先独立 Remux 再转码，则计 1+2。不能为了低分虚构不存在的直达转码能力。Probe、拓扑观察、身份核验、Import、最终验收等必要步骤不在首版评分范围，照常进入适用 Plan；不为它们发明新费用。

比较使用规范化的确定数值，显示的两位小数不参与排序；可用精确有理数比较。取分所用 s 来自本轮冻结候选 Evidence，不在执行过程中跟随实时做种数改写 Plan。

| 候选路径 | 总分 | 选择含义 |
| --- | ---: | --- |
| 本地材料转码达标 | 2 | 已有路径能达标时，沿既有规则无需额外寻源 |
| 1 个做种的外部文件直接达标 | 8 | 做种少的直接路径可能输给加工路径 |
| 20 个做种的外部文件转码达标 | 6.2 | 获取难易与加工动作已在同一分数中比较 |
| 50 个做种的原盘 Remux 达标 | 约 4.55 | 不因原盘身份被排除，也没有原盘特别奖励 |

## 4. 达标路径决策合同与执行落实

### 4.1 两层语义

| 概念 | 输入/输出与责任 | 不承担 |
| --- | --- | --- |
| 达标路径决策 | 根据当前目标、材料及候选Evidence、能力和已有结果，选择直接使用/获取/Remux/转码的必要组合及材料，给出代价和依据 | Event执行、重试、资源许可、Run生命周期 |
| 执行Plan | 将选定组合的一段或全部落实为原子Event、依赖、输入绑定、验证及输出合同 | 再次私自选择另一达标手段、降低Acceptance |

两层语义不要求增加两个物理服务、两个Runtime或新的顶层Domain。达标路径决策是Libra内部的确定性计算；是否由Coordinator调用独立纯函数、如何与现有Planner接口衔接，留到语义合同确认后的实现设计。

### 4.2 输入

- 当前Run及Execution Basis、冻结Acceptance和当前允许目标；
- 当前可合法使用的材料、已成功Workspace成果、身份/结构/Probe等Evidence；
- 若已完成搜索，同一冻结候选集合及做种声明；尚未搜索不伪造候选；
- 适用能力声明与可用性、已有合法策略结果和获取额度等既有约束；
- 版本化评分规则。瞬时队列、实时做种变化和资源许可不暗中改变同一输入的选择。

### 4.3 输出

成功决策包含选中材料或候选引用、必要手段组合及先后关系、预期闭合的Gap、成立依据与待实检条件、分项和总分、适用输入摘要。无可行选择时明确区分待补证、暂不可执行和已知不可达，交由既有过程机制处理；不创建新的业务状态机。

该输出可作为现有决策/Explanation中的有界值留痕，不预设新表、全局路径ID、路径队列或可独立恢复的路径对象。首版仅枚举适用的获取、Remux、转码组合，去除重复和无意义循环，不建设通用工作流搜索系统。

### 4.4 执行落实的一致性

Coordinator依照已形成的决定协调Work；现有Work Planner将对应工作编译为DAG。具体调用关系待定，但不能继续由Coordinator分支、候选Select和执行Planner分别作互相独立的手段选择。

Work按独立目标结果、幂等及恢复边界存在，不为整条路径再包一个与Run同目标的Work。一个决策可由一个或多个现有Work/Plan落实，不要求路径与Plan一对一。签发时要能追溯所消费的决定与Evidence；这是输入/Explanation一致性，不是在能力之间新增业务检查节点。

选路计分所依据的必要动作必须被执行编排落实；Probe、导入、验证等非计分步骤按适用合同加入。执行编排不能把已选Remux悄悄换成Transcode，Executor不能自行换源。真实新Evidence推翻原依据时回到路径决策，不以隐藏fallback继续。

### 4.5 证据与重新决策

沿用SSOT纯规划约束，不在计算时搜索Provider、读文件或Probe。已有材料可达标时不为比较价格额外搜索；需要外部材料时先通过显式观察取得候选。

同一执行Plan可以包含多个步骤。仅因下一步依赖上一步Result，不构成拆Plan理由；已声明typed binding可承接该结果。只有编译确需尚不存在的结构/Probe/施工参数，或存在正式Owner/Authorization边界，才按既有机制分阶段生成Plan，不改写旧Graph。

外部选择必须比较“获取加必要加工”的预计达标代价。下载前声明是规划依据，不是实际验收证明；已知证据不足以支持加工可达预期时先补证，不能靠零分或盲目下载填空。Series既有有界例外继续按自身合同处理。

实际取得材料后，若证据仍满足原路径条件，继续落实；若发现必须增加加工等实质变化，重新决策并保留变更依据。已下载材料作为已有输入，不重复加获取分、不自动换源；成功结果沿同Run正式合同复用。普通重试、设备等待或单个Event成功本身不触发重新选路。

尚未发生的副作用按新决策通过正式Work/Attempt机制承接，已执行或结果不确定的效果先依既有恢复合同厘清，不能同时派发相互冲突的路径。旧Plan和旧决策依据不改写；这些规则不增加路径生命周期。

## 5. 能力衔接与原盘输入

Planner 在 Plan 持久化前检查 typed ports 兼容；Runtime 依照 DAG 做结果绑定，不增加私有业务门禁。各 Executor 只承担自己声明的原子效果。

本次不是删除所有 Verify。SSOT 已声明的 Stability、Identity、Package、产品验证以及 Handle/Fence 校验各有独立目的。应移除的是在获取适配器里用文件数量替后续能力判断可加工性的限制，并修订与其一致的过窄合同。

SSOT §8.6.7 已支持 `ProductionSourceScopeReference` 的 stream_file/bdmv/dvd/iso，但 Remux 必须消费已冻结的主标题/片段顺序，不能自行调用 Probe、选择另一标题或启动其他 Capability。

因此统一职责为：

- 获取观察报告属于精确 Job 的真实成果及物理成员，不选正片、不代替下游验收。
- 拓扑/主标题观察由适用的显式原子能力产生 Evidence；复用现有底层解析库。如现有能力属于 Procurement scope，应通过 Libra 合法 scoped contract 复用 library，不能跨域调用 Procurement Executor。
- Planner 使用结构与 Probe Evidence，形成与来源无关的加工路径，冻结主标题及所需输入引用。
- Remux/Transcode 消费已授权、已明确的输入与 Intent，交付 Workspace 产品。最终 Verify 独立决定是否符合 Acceptance。

外部 BDMV 的合同需要表达“一个逻辑电影输入，包含多个物理文件”，保留目录相对布局、成员身份及主标题证据。不能把 29 个 m2ts 判作 29 部影片，不能把其中最大的文件冒充整个主标题。

沿用显式逐物理成员 Import，不在一个 Executor 内隐式批量导入。取得完整成员快照后再冻结有界 Import DAG，并建立可重建的同 Run 原盘 Source Scope。外部 Workspace 来源引用需要从仅 stream_file 扩展为可绑定结构化成员集合；原始 Procurement Binding 路径及各自授权仍分别保留。

不用通用的“只要是目录就接受”替换旧门禁；Job 归属、成员完整性及授权仍须成立。原盘成员/字节上限需在实现前以实际结构和现有 snapshot bounds 核定，不能静默裁剪成员或临时取消上限。

## 6. Plan 诊断记录

复用 SSOT 已有 Explanation Evidence，不建点数表或账本。建议记录：

- Planner/评分规则版本、目标与输入 Evidence 摘要；
- 候选路径标识、可行性或排除原因；
- 选中路径的动作分项、做种数及来源、预估总代价和选中理由；
- 尚待实检的预测条件，以及对应当前生成的执行节点范围。

分阶段情况下，必须区分“所选预计达标路径总分”和“本份 Plan 实际编译节点的分数范围”，避免把预计后续转码误记成当前已执行动作。两者只是同一 Explanation 内的诊断值，不跨 Plan 累加、不表示已消耗资源。无需对用户增加评分界面。

## 8. 狂暴女神与设计验收场景

本片原外部候选做种数 24；建议获取代价为约 4.034。若实际主标题仅需 Remux 即达标，总分约 5.034；若必须先 Remux 再转码，则约 7.034。只有现有能力实际支持原输入直接转码才可计约 6.034，不能为降分虚构路径。最大 m2ts 约 80 GB、原包约 85 GiB，不足以证明最终主标题大小或仅 Remux 可满足 50 GiB。

当前明确复现的是 MoviePilot 成果接入单文件门禁，并非已证明 FFmpeg Remux 本体失败。本地已有原盘路径也不等于本片已实际验证成功。原现场材料、旧 Run 的恢复处置与生产动作继续按 UAT-312 自身证据及授权处理，本设计不自动重开终态或重新下载。

后续实施至少验证：

1. 同目标下，多做种加工路径可击败少做种直接路径；总代价相等时稳定，候选输入顺序不影响选择。
2. 做种递增只降低获取代价；显示舍入不影响排序；同一冻结输入与规则版本可复现结果。
3. 不因成本低而接受不可达音轨/身份或提前降成 S1；0/unknown 做种不由公式自动准入。
