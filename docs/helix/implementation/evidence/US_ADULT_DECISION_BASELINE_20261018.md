# US Adult 五议题产品决定基线

日期：2026-10-18。来源：本线程 Product Owner 逐项确认。
本文仅冻结用户结果和开工取证，不是 Architecture SSOT、活动计划或生产授权。顺序只由 CURRENT_PHASE 管理。

## 1. 整理中的演员识别

- US Adult 每部影片恰好一位本库演员；抽取多张人脸只是匹配 Evidence，不引入多人出演管理。
- 算法选择匹配程度最高的有效演员，不把多候选交给用户消歧；成功阈值由工程验证确定。
- 无匹配及完全无脸统一进入既有暂存车间，由用户选择已有演员；用户也可纠正系统匹配。有演员关系才可上架。
- 整理页不提供建档或跳转快捷入口；保留既有 Subject/Run、席位、公平与原位继续，不通过重新 Intake 模拟确认。

## 2. 演员库生命周期

- 普通、JAV、US Adult 为三份独立身份库；现实同一人可各建一次，不跨库去重、共享业务档案或合并。
- 普通/JAV 系统全自动收纳、补全、归并和维护；用户只浏览资料及相关作品，不建档、确认、编辑、设置偏好、合并、停用或删除。
- 身份不足由系统有界再解析，不生成用户待办，不按同名强并，不阻塞正常影片整理。
- US Adult 全由用户建档：完全手动填写姓名并上传图，或输入姓名、辅助搜索肖像、选图确认。手动入口只服务此类，无类型选择。
- 必须有姓名和可用于识别的图片；允许改姓名、别名及补充/换图；本轮无合并、停用、删除。
- 搜索只准备供用户选择的图片；未选择前不注册或猜测出演关系，出站请求遵守既有全站 Integration Network Policy。
- 每次维护结束，演员页发布最多五位推荐；按人物聚合多影片线索，未处理项下轮重新筛选，不累积历史长待办。
- 优先覆盖更多暂存影片且截图可辨识的人物；有效项不足五位时不凑数；原始线索为受引用内部 Evidence。
- 用户从推荐认领已有演员或新建演员，同时确认截图来源 A 影片，A 解除该阻塞，无需二次确认。
- 只有明确 A 在本次 Intent 范围，不能凭聚类相似自动关联其他影片或改写已上架影片。

## 3. Arca 接管后的刷新

- 演员库新增、改名、换图不触发已上架 US Adult 的全量扫描、重识别或文件更新。
- 仅用户对单片手动指定或自动刷新演员，才创建本类 Aftercare Case；自动刷新选最高有效匹配，无结果保留原演员并提示。
- Case 连续更新演员关系、NFO、海报和依赖演员的标题/文件/目录名；同人资料变化也可由用户刷新采用最新资料。
- Shelf Entry、Deck Fact 和 Canonical Content Identity 不变；不退回 Libra，不改写历史 Accepted Package。
- People 只发布本域身份/参考资料，Libra/Arca 各自闭环；连续交互不等于共享 Store 或跨域原子事务。
- 这是演员更新类 Case 的来源限定，不取消普通健康问题既有自动 Case。

## 4. 每周维护窗口

- 可配星期和起止时间；默认周六 03:00–09:00 Asia/Shanghai，固定六小时，不是停稳后再计六小时。
- 进入时停止启动新正常工作并安全收敛；无法及时让出资源就跳过本轮并恢复供给，不强杀转码、不顺延结束时间。
- 退出时停止新维护批次，安全收尾并保存进度，未完成下周续跑；失败项不阻断其他任务。
- 用户主动安全停机优先，维护不得清除 stopped 意图；跨重启不重复 Effect 或伪造已完成。
- 概览仅显示维护状态和当前任务，无维护结果统计或历史报告页；结果仍在各业务页面显示。

最终确认的维护任务清单：

1. 收藏周期健康检查：Custody、Presentation、Conformance 检查及 Case 签发。
2. 普通/JAV 人物收纳、身份/资料/肖像维护，含 On-deck 人物 Evidence 的周期准备。
3. US Adult 未识别线索聚合和本轮五位推荐。
4. 豆瓣自动周期拉取；用户主动同步仍可在正常运行期间执行。
5. 重复收藏检测、退出策略建议评估；不增加删除授权。
6. 到期无引用工作区、临时 Artifact 和残留清扫。
7. 数据库轻量优化与内部引用抽查，不做 full VACUUM/历史清库。
8. 旧 Field Observation 明细到期保留清理。
9. 回收站既有到期规则下的清理；搬入、恢复及已开始操作的收尾仍是正常业务。

保留正常调度：Field 首次/增量观察、业务推进/兜底、Aftercare Case 执行、JAV Correction、上架交接、
已授权 Off-deck/Shelf Deregistration、本地评分 Resolution、消息投递/重试、页面投影、租约/超时/Effect Recovery、
活动清理责任及必要空间释放。健康检查签发的 Case 与 Libra Run 在正常模式执行；维护模式仍保留自身及安全收尾所需 Foundation 能力。

排除：不做备份产品功能，不新增全库媒体重识别，不自动授权媒体删除。

## 5. 海报和命名

- 海报保留四张影片截图，改成 2×2 大图，每张宽约海报一半；调整肖像占比，姓名/标题不遮截图。
- 肖像来自用户确认演员资料；初次整理和 Arca 用户刷新共用版本化生产规则。
- 命名为「演员名 + 原有命名」；完整保留原名主体，不另外拆分重写内容；扩展名与实际成品一致。
- 取消展示用自建番号及其文件名/标题/海报用途；内部 Domain-local identity、幂等键和收藏身份继续存在。
- 冻结最初原始文件名，后续从该原名重新生成，不能反复拿已加前缀的当前名当原名。
- 改演员只替换前缀；目标冲突明确报告，不覆盖文件或偷偷增加番号。
