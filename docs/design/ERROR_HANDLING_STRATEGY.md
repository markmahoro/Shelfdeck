# ERROR_HANDLING_STRATEGY — 统一错误处理策略

> **SSOT 路径**：`[ERROR_HANDLING_STRATEGY.md](./ERROR_HANDLING_STRATEGY.md)` · 文档索引 `[DOC_GOVERNANCE.md](../DOC_GOVERNANCE.md)`

本文档描述媒体管理服务与桌面客户端的统一错误处理策略，补充 `[DESIGN_TASK_CENTER.md](./DESIGN_TASK_CENTER.md)` **§17** 任务异常分类。

---

## 1. 错误处理原则

### 1.1 分层处理

- **领域层**：抛出领域异常（如 `TaskNotFoundError`、`InvalidStateTransitionError`），携带业务语义
- **应用层**：捕获领域异常，转换为 HTTP 错误响应或 IPC 错误事件
- **表示层**：展示用户友好的错误消息，提供恢复操作入口

### 1.2 错误分类

**可恢复错误**（Recoverable）：
- 用户可通过操作恢复（如重试、修改配置、释放资源）
- 应提供明确的恢复指导与操作入口
- 示例：网络超时、磁盘空间不足、权限不足

**不可恢复错误**（Fatal）：
- 系统内部错误、数据损坏、编程错误
- 应记录详细日志，引导用户联系支持或提交 issue
- 示例：数据库连接失败、配置文件损坏、未捕获的异常

**业务规则错误**（Business Rule Violation）：
- 违反业务约束（如原盘类资源不允许转码、同视频互斥冲突）
- 应在操作前预检，避免进入错误状态
- 示例：重复任务、状态转换非法、资源不满足条件

## 2. HTTP API 错误响应

### 2.1 标准错误格式

所有 API 错误响应应遵循 `openapi.yaml` 中定义的 `ErrorResponse` schema：

```json
{
  "error": {
    "code": "TASK_NOT_FOUND",
    "message": "Task with ID 'abc123' not found",
    "details": {
      "taskId": "abc123"
    }
  }
}
```

### 2.2 HTTP 状态码使用

- **400 Bad Request**：请求参数错误、业务规则违反
- **401 Unauthorized**：未认证或认证失败
- **403 Forbidden**：已认证但无权限
- **404 Not Found**：资源不存在
- **409 Conflict**：资源冲突（如同视频互斥、状态转换非法）
- **422 Unprocessable Entity**：请求格式正确但语义错误
- **500 Internal Server Error**：服务器内部错误
- **503 Service Unavailable**：服务暂时不可用（如媒体管理服务未启动）

### 2.3 错误码设计

错误码应具有层次结构，便于分类与处理：

- **TASK_***：任务相关错误（如 `TASK_NOT_FOUND`、`TASK_INVALID_STATE`）
- **LIBRARY_***：媒体库相关错误（如 `LIBRARY_ITEM_NOT_FOUND`）
- **CONFIG_***：配置相关错误（如 `CONFIG_INVALID_PATH_MAPPING`）
- **TRANSCODE_***：转码相关错误（如 `TRANSCODE_DEVICE_NOT_AVAILABLE`）
- **INTEGRATION_***：外部集成错误（如 `INTEGRATION_MOVIEPILOT_TIMEOUT`）

## 3. 任务异常处理

### 3.1 与 DESIGN_TASK_CENTER §17 的关系

`[DESIGN_TASK_CENTER.md](./DESIGN_TASK_CENTER.md)` **§17** 定义了任务异常分类（A1～F3），本节补充处理策略。

### 3.2 异常处理流程

**预检阶段**（A1～A3）：
- 在任务进入 `executing` 前完成所有可预检项
- 预检失败应将任务标记为 `failed_hard` 或保持 `pending_manual`，不占用类型任务槽
- 向用户明确说明失败原因与恢复步骤

**执行阶段**（B1～B6）：
- 捕获 FFmpeg 错误、文件系统错误、网络错误
- 删除不可信的 partial 文件，避免污染
- 记录详细错误日志（包括 FFmpeg stderr、系统错误码）
- 根据错误类型决定是否允许重试

**校验阶段**（C1～C3）：
- 校验失败必须删除 partial，不进入 replace
- 记录校验失败的具体原因（如码率不达标、元数据不一致）

**替换阶段**（D1～D5）：
- 整段 replace 自动重试 3 次（§5.4）
- 保留 `.etp.bak` 备份，避免数据丢失
- 第 4 次失败后进入人工介入，明示残留文件位置

**清理阶段**（E1～E2）：
- 清理失败不阻塞任务结案，标记为孤儿文件
- 提供孤儿扫描与一键清理功能

**系统级错误**（F1～F3）：
- 应用重启后扫描 `interrupted` 任务，提供恢复入口
- 记录系统级错误到独立日志文件，便于排查

### 3.3 重试策略

**自动重试**：
- replace 子流程：最多 3 次（写死）
- 网络请求（Emby API、MoviePilot）：指数退避，最多 3 次
- 文件系统操作：瞬时错误（如占用）可短暂重试

**不自动重试**：
- 编码失败（B4）：参数错误、编码器错误
- 校验失败（C1）：成片不合格
- 权限错误（A1、D5）：需用户修复配置

**用户手动重试**：
- 任务中心提供"重试"操作，重新入队
- 保留原任务记录与日志，便于排查

## 4. 前端错误展示

### 4.1 错误消息设计

**结构**：
- **标题**：简短描述错误类型（如"转码失败"、"配置错误"）
- **详情**：具体错误原因与上下文
- **操作**：恢复步骤或操作按钮（如"重试"、"查看日志"、"修改配置"）

**示例**：
```
标题：转码任务失败
详情：临时目录空间不足，需要至少 50GB 可用空间
操作：[修改临时目录] [查看详细日志]
```

### 4.2 错误展示位置

- **Toast 通知**：瞬时错误、操作反馈（3-5 秒自动消失）
- **任务卡片**：任务级错误，展示在任务列表中
- **模态对话框**：需用户确认的错误（如危险操作失败）
- **页面级横幅**：影响整个页面的错误（如媒体管理服务不可用）

### 4.3 日志查看

- 任务卡片提供"查看日志"入口
- 日志应包含：时间戳、任务 ID、错误类型、详细消息、堆栈跟踪（开发模式）
- 支持复制日志内容，便于用户反馈问题

## 5. 日志记录

### 5.1 日志级别

- **ERROR**：错误事件，需要关注与处理
- **WARN**：警告事件，可能导致问题但不影响核心功能
- **INFO**：关键业务事件（如任务状态变更、配置保存）
- **DEBUG**：详细调试信息（仅开发模式）

### 5.2 日志内容

**必须包含**：
- 时间戳（ISO 8601 格式）
- 日志级别
- 模块/组件名称
- 消息内容

**可选包含**：
- 任务 ID、用户 ID、会话 ID（便于追踪）
- 错误堆栈（ERROR 级别）
- 请求 ID（API 调用）

### 5.3 日志存储

- **媒体管理服务**：日志文件位于 `~/.emby-third-party/logs/media-service.log`
- **桌面客户端**：日志文件位于 `~/.emby-third-party/logs/desktop.log`
- **日志轮转**：单文件最大 10MB，保留最近 5 个文件

## 6. 监控与告警

### 6.1 关键指标

- **任务失败率**：按 actionType 分类统计
- **API 错误率**：按端点与错误码分类
- **平均恢复时间**：从错误发生到任务恢复的时间

### 6.2 告警规则（可选）

- 任务失败率超过 10%（1 小时窗口）
- 媒体管理服务连续 3 次健康检查失败
- 磁盘空间低于 10GB（临时目录或目标目录）
